# Как внести изменения

Спасибо за интерес к проекту. Прочитайте этот документ перед тем, как открыть pull request.

Дизайн фич, протоколы и проверки на устройстве описаны в [docs/](docs/). Файл [CLAUDE.md](CLAUDE.md) — инструкция для ИИ-агента, который работает с кодом в этом репозитории.

## Перед началом

### Исправления ошибок

Если нашли ошибку и хотите её исправить, делайте. В описании PR укажите связанный issue или опишите ошибку и шаги её воспроизведения.

### Новые функции

Pull request — это запрос на то, чтобы мы проверили, приняли и поддерживали изменение. Большие изменения требуют согласования до написания кода: сначала опишите идею в issue, затем пишите код.

Перед тем как писать код новой функции:

1. Поищите похожие обсуждения в issues и discussions.
2. Откройте issue с описанием проблемы и предлагаемого решения.

## Pull request

### Перед отправкой

- **Найдите похожие PR**, чтобы не дублировать работу.
- **Проверьте изменения локально.** Сборка, unit-тесты и, если затронуто воспроизведение или жизненный цикл, проверка на устройстве.
- **Одна задача на PR.** Исправление и новая функция — разные PR.

### Что проверяется при ревью

- **Работает ли?** Проверено локально, тесты проходят, регрессий нет.
- **Поддерживаемо ли?** Понятный код, разумная сложность, разделение ответственности.
- **Подходит ли?** Соответствует дизайну фич и принципам проекта, описанным в `docs/`.
- **Ограничен ли объём?** Решает заявленную задачу без лишних дополнений.

### После отправки

- Отвечайте на замечания ревью.
- Если PR устарел, обновите его на актуальной основной ветке.

## Сборка и тесты

Нужны JDK 21 и Android SDK. Команды из корня проекта:

```bash
JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 \
PATH="$JAVA_HOME/bin:$PATH" \
./gradlew testDebugUnitTest assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

### Непрерывная интеграция

GitHub Actions (`.github/workflows/ci.yml`) запускается на каждый push в `main`, в ветки `ci/*` и на теги `v*`, и на каждый pull request. Он прогоняет unit-тесты, собирает debug APK и проверяет, что instrumentation- и BlackBox-тесты компилируются. Перед просьбой о ревью убедитесь, что ваш pull request зелёный. Тесты, которым нужно устройство, в CI не запускаются. После зелёного push в `main` workflow `Publish test APK` публикует тестовый APK с debug-подписью на GitHub Pages (постоянная ссылка в README; релиз и тег не создаются); он нужен только для проверки, не для production.

## Стандарты кода

- **Kotlin и Compose**: соблюдайте стиль существующего кода. Не добавляйте библиотеку, если текущий стек уже решает задачу.
- **Тесты**: JVM-тесты используют JUnit 5, instrumentation-тесты — JUnit 4.
- **Безопасность**: не выводите в логи и не публикуйте cookies, пароли, PIN и URL с секретами. Не отключайте проверку TLS и не используйте trust-all. Не помещайте учётные данные в URL.
- **Документация**: в `docs/` не вписывайте серийные номера устройств, внутренние IP-адреса и топологию домашней сети; используйте плейсхолдеры (`<device-serial>`, `<frigate-lan-ip>`).

## Исправление ошибки в коде

1. Напишите минимальный тест, который воспроизводит ошибку.
2. Запустите его и убедитесь, что он падает по правильной причине.
3. Внесите минимальное изменение в код.
4. Запустите тест повторно и убедитесь, что он проходит.
5. Запустите весь набор unit-тестов и соберите debug APK.

Для изменений, которые касаются воспроизведения видео, WebSocket, WebView или жизненного цикла Android, компиляции и unit-тестов недостаточно: проверьте поведение на физическом устройстве.

## Тесты на устройстве

Не запускайте `connectedAndroidTest` на телефоне, где стоит ваше приложение: Gradle удаляет приложение вместе с данными (профиль сервера, сессия, учётные данные). Ставьте и запускайте так:

```bash
adb -s <serial> install -r app/build/outputs/apk/debug/app-debug.apk
adb -s <serial> install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s <serial> shell am instrument -w \
  -e class com.frigate.android.feature.live.LiveCameraTileTest \
  com.frigate.android.test/androidx.test.runner.AndroidJUnitRunner
```

Если подключено несколько устройств, всегда указывайте `-s <serial>`.

## Искусственный интеллект

Если вы использовали ИИ-инструменты, вы отвечаете за код, который отправляете: проверьте его, протестируйте и сможете объяснить каждую строку.
