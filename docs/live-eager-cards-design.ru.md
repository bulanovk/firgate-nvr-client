# Live: все карточки камер сразу (вариант 1)

Статус: реализовано (2026-11-02). Решение владельца: вариант 1 — заменить ленивую сетку на прокручиваемую колонку, чтобы все карточки камер существовали при открытии раздела Live.

Что сделано:
- `LiveCameraScreen.kt`: `LazyVerticalGrid` заменён на `Column` с `verticalScroll`; ряды по две камеры при `expanded`, нечётная последняя камера сохраняет ширину колонки.
- Видимость считается по `ScrollState` и границам карточек в координатах контента (`onGloballyPositioned`); пока открыта камера, видимых в сетке нет.
- `LiveTilePolicy.kt`: `liveSnapshotInterval(..., attempted)` — невидимая карточка без попытки загрузки получает один снимок, затем опрос выключен.
- `MainActivity.kt`: состояние прокрутки Live — `ScrollState` вместо `LazyGridState`; сетка Events не менялась.
- Проверки: RED `hiddenCameraLoadsOneStillBeforeItIsEverVisible` (JVM, падение на утверждении); на устройстве то же поведение проверяет снаружи процесса UiAutomator-тест `LiveFeedTest.everyCameraStillIsRequestedBeforeAnyScroll` (снимок последней из пяти камер запрашивается без единой прокрутки); полный unit-набор.
- Не проверено: память и число одновременных запросов при большем числе камер; прокрутка до нижних карточек на устройстве.

Основа: PWA (`LiveDashboardView.tsx`, `CameraImage.tsx`) монтирует все карточки сразу; отложенность снимков там даёт браузер (`loading="lazy"`), видимость (`IntersectionObserver`, порог 0.5) управляет только стримами. Сверка с checkout PWA, версия не сопоставлена с развёрнутой.

## Проблема

- `LiveCameraScreen.kt` (`LazyVerticalGrid`) компонует только видимые элементы. Карточка за экраном не существует, её `LaunchedEffect` с первым снимком не запускается.
- `liveSnapshotInterval` (`LiveTilePolicy.kt`) при `visible = false` возвращает `-1`: даже смонтированная карточка за экраном не получит снимок.

Поэтому одной заменой контейнера задача не решается: нужны оба изменения.

## Проектное решение

1. **Контейнер.** `LazyVerticalGrid` → `Column(Modifier.verticalScroll(scrollState))`. Камеры раскладываются рядами: при `expanded` (ширина ≥ 600 dp) по две в ряд через `Row` с `weight(1f)`, иначе по одной. Заголовок карусели отзывов остаётся первым элементом.
2. **Состояние прокрутки.** `LazyGridState` → `ScrollState`. Поднятое состояние в `MainActivity` (`val grid = rememberLazyGridState()`, строка ~330) меняет тип; отдельная сетка Events не трогается. Сохранение позиции при уходе в архив сохраняется, так как состояние остаётся выше ветвей экрана.
3. **Видимость для плеера.** `visibleCameraIds` (`CameraVisibility.kt`) принимает границы в координатах контента. Каждая карточка сообщает свои границы через `onGloballyPositioned`; viewport = `[scrollState.value, scrollState.value + высота окна]`. Порог 50 % и `visibleCameraIds` сохраняются, меняется только источник данных. Видеопоток по-прежнему запускается только для видимых (политика не меняется).
4. **Первый снимок для невидимых.** Новое правило в `liveSnapshotInterval`: карточка без снимка, которая не видна, получает одну загрузку (интервал 0 один раз), после неё опрос отключается, пока камера не видна. Для видимых и отключённых/оффлайн камер поведение прежнее. Требуется параметр `hasSnapshot`.
5. **Высота карточки.** В `verticalScroll` высота ограничена бесконечностью. В `LiveCameraTile.kt` (строка ~107) расчёт `maxWidth / maxHeight` даст 0 при бесконечной высоте. Высоту карточки задаёт `tileAspect` от `detectWidth/detectHeight` через `aspectRatio`, а не родитель. Это надо проверить тестом.

## Риски

- **Одновременные запросы.** OkHttp по умолчанию держит 5 запросов на хост, поэтому снимки идут не все разом: это естественное ограничение. Проверить на устройстве.
- **Память.** Каждый снимок декодируется до 720 px по высоте (~3.7 МБ ARGB на кадр 16:9). При 10 камерах это около 37 МБ, при большем числе станет заметно. Нужен замер числа камер на устройстве; возможный вариант — `inSampleSize` по размеру карточки.
- **Трафик и нагрузка сервера.** При открытии раздела N запросов `latest.webp`. Периодический опрос остаётся только для видимых, поэтому постоянная нагрузка не растёт.

## План работ (TDD по CLAUDE.md)

1. RED, JVM: `liveSnapshotInterval` для невидимой карточки без снимка возвращает 0 (один раз), с снимком — `-1`.
2. RED, JVM: видимые ids из `scrollOffset` и границ контента (чистая функция, без Android-импортов).
3. GREEN: правило интервала и функция видимости.
4. RED на устройстве (UiAutomator): снимок последней камеры запрашивается без прокрутки.
5. GREEN: `Column` + `verticalScroll`, ряды по ширине, `ScrollState` в `MainActivity`.
6. Полный unit suite (`testDebugUnitTest`), `assembleDebug`.
7. Устройство (`adb install -r`, без `connectedAndroidTest`): снимки всех камер до прокрутки; видео не стартует для невидимых; повороты экрана (`LiveCameraTest.theCameraStaysOpenAfterTheRotation`); замер памяти и числа одновременных запросов.

## Открытые вопросы

- Сколько камер у владельца? От этого зависят память и нужность `inSampleSize`.
- Нужна ли виртуализация для большого числа камер? Сейчас предполагается, что нет.
