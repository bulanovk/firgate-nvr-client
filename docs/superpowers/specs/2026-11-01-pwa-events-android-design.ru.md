## Цель и границы

Заменить нынешний текстовый список `/api/events` полноценным разделом Review/Events. Это один согласованный объём работ: **Alerts, Detections, Motion, переход в History, фильтры, свайпы, мультивыбор, Export/Delete и правая шкала в широкой раскладке**. Порядок технических задач не является переносом функций во «вторую фазу».

Android 12+, minSdk 31, compileSdk/targetSdk 35. Kotlin 2.2.10, AGP 9.4.1, Java 21, Compose BOM 2024.12.01, Material 3; существующие Gson, OkHttp и Media3. Без новых библиотек, WebView, Hilt, Retrofit, Room, DataStore или Kotlin Serialization. JVM — JUnit 5, instrumentation — JUnit 4.

Не переносим desktop hover, клавиатурные команды и mouse-wheel zoom. Touch pinch переносим. Не добавляем Wi-Fi routing и новую систему воспроизведения архива. Не меняем принятый дизайн Live/History.

## Экран и визуальная иерархия

- Тёмная схема, согласованная с Live/History. Без собственного большого заголовка «Recent events» и старых текстовых карточек.
- Три типа: Alerts / Detections с реальными счётчиками; Motion без придуманного количества. Числа 206/3 — только данные демонстрации, не константы приложения.
- В narrow нет правой шкалы; в wide она есть. Техническое решение для Android: wide от `600.dp`, в рамках принятой широкой композиции. Сетка адаптируется к доступной ширине без горизонтального скролла всего Android-экрана.
- Карточка: авторизованное превью, время/длительность, цвет severity, объектные/аудио-пиктограммы, ongoing, reviewed, дополнительные метаданные только при наличии. Плашка имени камеры сохраняется как согласованное отличие от PWA.
- Камеры и Show Reviewed остаются отдельными действиями шапки; narrow gear открывает настройки даты/общих фильтров, а не переключает reviewed. В wide дата и общие фильтры доступны в шапке.
- Фильтры Review: камеры, Last 24 Hours либо календарный день, labels, zones, включение другой severity, Show Reviewed. Motion: камеры, дата, Motion Only; общие review-фильтры и Show Reviewed к Motion не применяются.
- Строки «All labels» и «All zones» видны всегда (как `ReviewFilterGroup.tsx`), даже когда в загруженных записях нет зон. Включение очищает выбор, выключение ничего не делает; последнюю отмеченную метку или зону снять нельзя. Списки меток и зон берутся только из загруженных записей.
- Явные loading / empty / filtered-empty / retry; ошибка обновления не стирает уже загруженные карточки. Диалоги и popup используют тёмные цвета, не дефолтную светлую тему.
- Действия доступны через semantics/TalkBack; свайп не единственный способ отметить просмотренным или начать preview. Цвет не единственный носитель severity/selection.

## Взаимодействия

1. Тап review-карточки открывает **существующий History**, камера нажатой карточки, позиция `startTime - 4 s`. Отправка отметки viewed начинается сразу при открытии, не после первого видеокадра. Ошибка отметки не блокирует архив и не выдаётся за успех.
2. Back возвращает именно в исходную вкладку Events с прежними фильтрами, положением сетки и выбранным типом. Исторический день открывает соответствующий диапазон History, а не зажимается сегодняшним окном. Повторный тап той же карточки из Events заново позиционирует на её начало; существующее resume-поведение Live не ломается.
3. Свайп влево — viewed только для завершённого непросмотренного review; вправо — inline preview, **не History**. Long press — выбор. Вертикальный скролл, tap, swipe и long press не должны запускаться одновременно. Выбор обведён цветом severity; не добавлять выдуманные круглые чекбоксы поверх превью.
4. При выборе шапку заменяют `N selected`, Unselect, Export, reviewed/unreviewed, admin Delete. Операции используют snapshot выбранных id. Повторный тап отправки не дублирует запрос. Mark all включает только завершённые подходящие review.
5. Просмотрено/удалено отражается после успешного серверного ответа; при неуспехе — ошибка и повтор. Обновляются список, summary и Live-карусель. Обратная отметка reviewed=false поддерживается.
6. Export: один review и пакет до 50, реальные задания сервера, статус и получение готового файла. Export не равен toast или локальному изменению списка. Delete доступен только admin, с подтверждением и предупреждением об удалении связанных записей. Реальные разрушительные проверки на данных пользователя требуют отдельного разрешения.
7. WebSocket `reviews` используется как invalidation, не как полный журнал. Новые review не сбивают текущий скролл: появляется действие загрузки новых событий. После reconnect/возврата — REST reconciliation; новые фильтры не могут быть перезаписаны старым ответом.
8. Широкая правая шкала и обзор диапазона используют тот же набор данных/временное окно, что сетка; tap сегмента ведёт к карточке, pinch меняет масштаб. На narrow шкала отсутствует, включая Motion; управление временем Motion остаётся в собственной панели.

## Motion и inline preview

Motion — синхронные ускоренные previews камер с общим wall-clock временем, play/pause/seek и скоростями **4, 8, 12, 16**. Отдельное меню камеры открывает её Motion previews по диапазону. Выбор записи ведёт в History на выбранное время без фальшивого review-id и без отметки viewed.

Preview — не live MSE и не полноценный HLS-плеер на каждую карточку. Используем реальные preview-ресурсы сервера и native Media3. Часы нескольких камер синхронизируются по wall-clock; пробел записи не превращается в кадр другой камеры или зависший «живой» preview. Скрытые плитки не держат декодеры; выход с Events и Activity STOP освобождают media и останавливают polling.

Motion Only означает **движение без object-review**: пропускаются 30-секундные интервалы без положительного motion либо с пересечением alert/detection или review с detections/objects; ongoing заканчивается в now. Обычный шаг общего времени — 0.5 s. Per-camera clips всегда строятся из motion-only диапазонов: bucket 15 s, дубли start объединяются MAX motion, исключаются object-review этой камеры, сливаются только соседние интервалы с допуском 0.001 s. Это не просто подсветка кнопки или фильтр motion > 0. Пространственные функции Motion previews опираются на **16×16 `motion_heatmap` записей**, взвешенную длительностью пересечения записей с окном (знаменатель включает записи без heatmap). Она управляет затемнением неактивных ячеек, фильтром области и crop. Временной scalar `motion` не позволяет восстановить пространственные зоны. При отсутствии heatmap пространственные действия недоступны с объяснением; не генерируем жёлтые прямоугольники. Выбор области применяется только по Apply, сбрасывается при смене камеры, совпадение — любая выбранная ячейка с интенсивностью > 0; crop по bounding rectangle, включён по умолчанию; dim по умолчанию 82%.

Ограничения принятого HTML не становятся ограничениями Android: кадры синтетические, preview имитируется, Export/Delete локальные, Motion Only не выполняет реальный skip, heatmap отсутствует. В плане эти функции реализуются и проверяются на настоящих данных; макет доказывает согласованный вид и переходы, но не работоспособность транспорта.

## Данные, состояние и безопасность

- Review list + `/api/review/summary`, timezone выбранного календаря. Для Last 24 Hours — `last24Hours`, для дня — соответствующая запись `YYYY-MM-DD`. Без Show Reviewed число равно `max(total - reviewed, 0)`, с ним — total. Счётчики не выводятся из количества загруженных карточек.
- Все ограничения загрузки явные. Нельзя молча обрезать день до 2000 карточек, показывая summary целого дня как будто список полный. План предусматривает проверяемую ограниченную загрузку по временным окнам и явное сообщение при недостижимой полноте.
- Events session принадлежит ConnectedApp и переживает History/поворот; media принадлежит видимому экрану. Один существующий activity socket, fan-out invalidation для Live и Events, без второго socket.
- Никакого глобального Loading/LoginRequired из-за обычной ошибки Events. 401 любого нового транспорта ведёт в существующий SessionRenewal. CancellationException не превращается в ошибку UI. Смена profile/cookie изолирует данные и сбрасывает старые запросы.
- Cookie только в заголовке Cookie, URLs относительно ServerProfile; без credentials в URL, без trust-all TLS и без утечки cookie через redirects. Медиа-пути валидируются и ограничиваются origin/base path. Ответы JSON ограничены существующими 16 MiB; preview/download потоковые, без загрузки всего видео в память.
- Нельзя делать коммиты без явного запроса. На устройстве только `adb -s <serial> install -r` + `am instrument`, не connectedAndroidTest, не uninstall, не очистка данных/logcat и не изменение системного поворота.

## Подтверждение реализации

Каждая поведенческая задача: RED из правильной причины → минимальный GREEN → regression suite. До завершения: полный JVM suite, debug APK, instrumentation narrow/wide и физический device smoke реальных preview/History/rotation/lifecycle/session renewal. Компиляция, HTML и unit-тесты не подтверждают native playback.

При выполнении сверять интерфейс с принятой rev4, а не рисовать новую интерпретацию PWA. Непроверенные возможности и отсутствующие условия теста записывать явно. Этот документ фиксирует принятый scope и технические решения плана; сам по себе не утверждает, что Android уже реализован или проверен.
